# Private support attachments

Admins can attach up to five files per private support message, up to 5,000,000 bytes each. Supported formats: PNG, JPEG, WebP, PDF, DOCX, XLSX, UTF-8 TXT and CSV. Older DOC/XLS, macro-enabled Office documents, SVG, HTML, executables and arbitrary ZIP files are not accepted. Each message needs a text caption. The composer provides a separate photo/gallery picker and document picker, accepts multiple selections, appends files up to the limit, and allows individual removal before sending. Selected files remain File references until Send; encoding is sequential at send time. Image previews are opened on demand, one at a time, using temporary object URLs that are revoked on close/removal/unmount. This reduces selection-time memory; the final upload still needs encoded request memory. The operating system determines the native photo-picker appearance. Users see images or download cards in Help & Support. Only admins can upload; recipients can view and download.

Files are stored atomically with the message in PostgreSQL. History responses contain filenames, MIME types and decoded sizes, never file contents. Each file URL checks the signed-in conversation owner or ADMIN role, returns private/no-store with nosniff, and downloads documents using Content-Disposition. Office files must contain the expected ZIP-directory entries; encrypted and VBA-bearing packages are rejected. Format checks do not constitute malware scanning. Existing single-image messages remain available through their original endpoint. The existing send rate limit, bell notifications and retry protection apply; attachment differences cause a conflicting retry to be rejected. No support email is sent.

Deploy migration 0032_support_files.sql before restarting the app. Pull main, run bun install, bun run db:migrate and bun run build, then restart investfund.service. No other workers need restarting. In Admin → Support inbox, select the user, choose files, write a caption, and Send message. A five-file maximum request is about 34 MB after base64 encoding; reverse-proxy request limits must accommodate it. If Nginx returns 413, configure client_max_body_size 35m in the applicable Hestia domain proxy configuration and validate/reload Nginx. Retain this setting through Hestia's supported custom template rather than relying on an overwritten generated configuration.

Tests cover mixed-file messages, duplicate retries and attachment conflicts, metadata-only history, owner/admin retrieval, blocked unrelated and anonymous downloads, non-admin uploads, file count/size/type/name validation, and Word/Excel ZIP-directory verification. For larger attachment volume, migrate to private object storage.
